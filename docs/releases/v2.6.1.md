# NodeCast TV Plus v2.6.1

v2.6.1 Improves Live TV navigation and playback, adds optional flat-list and startup-playback modes, and refreshes current runtime and workflow dependencies.

---

### Highlights

- Settings > Preferences can show Live TV as one flat, account-specific channel list. The list remains bounded while scrolling, searches the complete catalogue server-side, retains source filtering and favourites, and supports channel-number or alphabetical ordering ([#399]).
- Optional startup playback can resume the last active channel or start the first available channel. Missing or hidden targets fall back safely, and browsers that block audible autoplay receive a visible muted retry instead of a stalled player ([#401]).
- TV Guide selections now start the intended channel even when the bounded Live TV sidebar has not loaded it yet ([#389]).
- M3U media remains authorized when the playlist and media URLs use different hosts, without allowing unrelated URLs ([#394]).
- Raising or removing a quality cap restores the appropriate direct or remux path and reports the active playback method accurately ([#397]).
- Maintenance refreshes current runtime and npm dependencies, the browser-test toolchain, and pinned GitHub Actions used for CI, CodeQL, and multi-architecture container publication ([#383], [#376], [#391], [#392]).

---

### Upgrade from v2.6.0

Back up `/app/data`, pull the release image from either registry, and recreate the container with the same data volume and deployment secrets:

```bash
docker pull ghcr.io/mikaelkw/nodecast-tv-plus:2.6.1
```

or:

```bash
docker pull mikaelkw/nodecast-tv-plus:2.6.1
```

No manual database migration is required. Preserve the existing strong, distinct `JWT_SECRET` and `SESSION_SECRET` values, and preserve `TOTP_ENCRYPTION_KEY` when authenticator-app 2FA is in use.

Stable tags for this release are `2.6.1`, `2.6`, and `latest`.

To roll back, stop the upgraded container, restore the pre-upgrade data backup, and recreate the container with 2.6.0 and the original deployment secrets. Do not assume that simply starting an older image against upgraded data is a safe rollback.

### Validation

- Focused production and local testing covers bounded flat-list loading, ordering, complete-catalogue search, source filtering, favourites, playback, startup selection, browser-policy muted playback, quality transitions, and cross-host M3U media.
- The exact combined testing image passed source synchronization, sessions, settings persistence, Live TV and guide navigation, sustained and switched playback, sign-out/sign-in, and authenticator-app 2FA checks.
- Automated release gates cover application and browser/media behavior, mobile WebKit, reverse-proxy subpaths, dependency and runtime-image scanning, CodeQL, container health, and supported migrations.
- Migration validation targets supported upstream v2.1.1 and 2.1.4 data and the published Plus v2.6.0 image. Final release artifacts are checked for both `linux/amd64` and `linux/arm64` and matching registry aliases.

---

### Known limitations and deferred follow-up

- Browser autoplay rules may require startup playback to begin muted. Sound can then be enabled normally in the player.
- Multi-source filtering remains covered by controlled tests because the production validation environment contains one M3U provider.
- The unreproduced failed Home-favourite startup report remains tracked in [#361].
- Major Express and better-sqlite3 upgrades remain deferred for separate compatibility work.
