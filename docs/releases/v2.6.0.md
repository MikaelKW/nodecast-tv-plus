# NodeCast TV Plus v2.6.0

NodeCast TV Plus v2.6.0 improves large-provider browsing, live playback-session reliability, subtitle customization, and Movie/Series timeline feedback.

---

### Highlights

- Home resolves favourite channels without downloading the full Live TV catalogue. Live TV loads groups progressively, searches the complete catalogue server-side, and retains stable scrolling and group state ([#334]).
- Search totals represent all matches from the start. Collapsed groups do not download thousands of channels; expanded groups load bounded pages as browsing continues ([#365], [#367]).
- Tab-owned playback leases replace superseded live sessions and reclaim abandoned FFmpeg work. Intentionally paused open tabs remain active. Interrupted live inputs reopen without ranged resume, and the validated quality-change path remains stable ([#339]).
- A shared HTML subtitle overlay gives ordinary browser playback and web fullscreen consistent rendering, with native fallback where the platform controls playback ([#341]).
- Settings > Preferences adds a preferred subtitle language and No subtitles, Default, Forced only, and Always preferred modes. Viewer accounts can access their own preferences without access to global administration ([#344]).
- Account-specific appearance settings control subtitle size, colors, background opacity, edge style, and vertical position, with a live preview ([#346]).
- Movies and Series show total duration when reliable metadata is available ([#349]).
- The backend proxy reports unsupported VOD byte-range seeking accurately when an upstream provider ignores a range request, rather than advertising unsupported seeking ([#353]).
- Maintenance includes Trivy 0.74.0, weekly Dependabot configuration, the adaptive README logo, and clearer release-validation wording ([#351], [#355], [#357], [#359]).

---

### Upgrade from v2.5.4

Back up `/app/data`, pull the release image from either registry, and recreate the container with the same data volume and deployment secrets:

```bash
docker pull ghcr.io/mikaelkw/nodecast-tv-plus:2.6.0
```

or:

```bash
docker pull mikaelkw/nodecast-tv-plus:2.6.0
```

No manual database migration is required. Preserve the existing strong, distinct `JWT_SECRET` and `SESSION_SECRET` values, and preserve `TOTP_ENCRYPTION_KEY` when authenticator-app 2FA is in use.

Stable tags for this release are `2.6.0`, `2.6`, and `latest`. The existing `2.5` line is not moved to 2.6.0.

To roll back, stop the upgraded container, restore the pre-upgrade data backup, and recreate the container with 2.5.4 and the original deployment secrets. Do not assume that simply starting an older image against upgraded data is a safe rollback.

### Validation

- Combined controlled-local and large-production-catalogue testing covered browsing, favourites, search, playback, session cleanup, duration, subtitles, and restart behavior in Firefox, Chromium, and physical iPhone Safari.
- Focused production validation covered collapsed groups with more than 24,000 search matches, bounded continuation, complete counts, and stable collapse/re-expansion.
- Automated release gates cover application and browser/media behavior, mobile WebKit, reverse-proxy subpaths, dependency and container scanning, CodeQL, and container health.
- Migration validation targets supported upstream v2.1.1 and 2.1.4 data and the published Plus v2.5.4 image. Final release artifacts are checked for both `linux/amd64` and `linux/arm64` and matching registry aliases.

---

### Known limitations and deferred follow-up

- Large-source startup and synchronization may still involve heavy I/O. A startup-readiness sign-in gate is tracked separately in [#337].
- The confirmed abandoned-session lifecycle path is corrected. The original intermittent FFmpeg CPU report in [#299] does not establish that every possible provider-related high-CPU cause has been eliminated.
- iOS native fullscreen uses platform subtitle styling. Broader native-fullscreen VOD seeking remains tracked in [#235].
- The range-capability correction does not add seeking support to a provider that cannot honor byte ranges ([#192]).
- Failed Home favourite startup can leave the Live TV list empty ([#361]); TV Guide navigation may not start the selected channel ([#362]); some quality transitions can show an inaccurate playback-method label ([#364]). These non-blocking follow-ups remain outside this release.
- Broader compatible-VOD direct playback and ranked subtitle-language fallbacks remain future work ([#363], [#343]).
