# NodeCast TV Plus v2.5.0

NodeCast TV Plus v2.5.0 adds audio-track and subtitle selection, strengthens long-form VOD playback across desktop and mobile browsers, and makes stable container images available from both GHCR and Docker Hub.

---

### Highlights

- Choose available audio tracks and subtitles directly in Movie and Series playback by @MikaelKW in [#213].
- Preserve playback position when changing audio tracks by @MikaelKW in [#216].
- Stabilize the VOD scrubber and unbuffered seeking during transcoded playback by @MikaelKW in [#219] and [#221].
- Load embedded subtitles on demand for long-form VOD and recover them after far seeks by @MikaelKW in [#224] and [#226].
- Align seeked audio, improve Firefox overlay performance, and stabilize cross-browser subtitle timing by @MikaelKW in [#228] and [#230].
- Make all Movie and Series cards reachable in iPhone Safari by @MikaelKW in [#233].
- Normalize subtitle presentation across Chromium, Firefox, and iPhone Safari by @MikaelKW in [#242].
- Hide the scroll-for-details hint during fullscreen playback by @MikaelKW in [#244].
- Isolate authentication cookies between NodeCast TV Plus installations sharing one hostname by @MikaelKW in [#246].
- Mirror stable amd64 and arm64 release images to Docker Hub while retaining GHCR as the canonical registry by @MikaelKW in [#248].

---

### Upgrade from v2.4.0

Back up the existing `/app/data` volume, pull the release image from either registry, and recreate the container with the same volume and deployment secrets:

```bash
docker pull ghcr.io/mikaelkw/nodecast-tv-plus:2.5.0
```

or:

```bash
docker pull mikaelkw/nodecast-tv-plus:2.5.0
```

No manual database migration is required. Keep the existing strong, distinct `JWT_SECRET` and `SESSION_SECRET` values. If authenticator-app 2FA is enabled, also preserve the existing `TOTP_ENCRYPTION_KEY`.

Matching stable tags are published to both registries:

- `2.5.0` — this exact release
- `2.5` — newest compatible 2.5 patch release
- `latest` — newest stable release

To roll back, stop the upgraded container, restore the pre-upgrade data backup, and recreate the container with `2.4.0` and the existing deployment secrets.

---

### Validation

- Application, authentication, TOTP, OIDC, dependency, proxy, browser/media, mobile WebKit, reverse-proxy subpath, Docker, release-metadata, and migration checks passed.
- The automated release gate verified supported upstream v2.1.1 and 2.1.4 migrations and an upgrade from the published Plus v2.4.0 image.
- Hands-on validation covered audio and subtitle switching, position-preserving track changes, long-form playback and seeking, subtitle recovery and synchronization, fullscreen behavior, mobile catalogue scrolling, multi-instance authentication isolation, and a consolidated private-browser smoke test.
- A pre-release Docker Hub validation build confirmed matching `linux/amd64` and `linux/arm64` platform digests across both registries, plus container health and readiness.

---

### Known limitation

Far seeking in iPhone Safari's native fullscreen player can be limited by WebKit's view of the currently generated HLS window. Embedded NodeCast controls and ordinary desktop seeking are unaffected. The architectural follow-up is tracked in [#235].
