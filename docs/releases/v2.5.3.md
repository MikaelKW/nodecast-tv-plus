# NodeCast TV Plus v2.5.3

NodeCast TV Plus v2.5.3 is a maintenance release focused on large-provider reliability, content visibility, release awareness, channel completeness, and a smaller production container.

---

### Highlights

- Check the installed version and latest stable GitHub release from a dedicated About tab, with automatic checks limited to once every 24 hours and an explicit manual action ([#4]).
- Show or hide all currently filtered Manage Content results while retaining an explicit Save Changes step ([#3]).
- Preserve independent 4K, FHD, HD, and SD channel variants instead of collapsing them by normalized names ([#266]).
- Retain the last-known-good Live TV and EPG catalogue when a transient refresh still fails after its bounded retry ([#273]).
- Keep large-playlist refresh controls locked from preflight estimation through warning handling, synchronization, and cleanup ([#298]).
- Preserve source-wide and individual visibility choices across later synchronization and container restarts ([#3]).
- Reduce the production image footprint and refresh its runtime packages while retaining the required media and hardware capabilities ([#283]).

---

### Upgrade from v2.5.2

Back up the existing `/app/data` volume, pull the release image from either registry, and recreate the container with the same volume and deployment secrets:

```bash
docker pull ghcr.io/mikaelkw/nodecast-tv-plus:2.5.3
```

or:

```bash
docker pull mikaelkw/nodecast-tv-plus:2.5.3
```

No manual database migration is required. Keep the existing strong, distinct `JWT_SECRET` and `SESSION_SECRET` values. If authenticator-app 2FA is enabled, also preserve the existing `TOTP_ENCRYPTION_KEY`.

Matching stable tags are published to both registries:

- `2.5.3` — this exact release
- `2.5` — newest compatible 2.5 patch release
- `latest` — newest stable release

To roll back, stop the upgraded container, restore the pre-upgrade data backup, and recreate the container with `2.5.2` and the existing deployment secrets.

### Validation

- Application, authentication, resource-control, update-check, channel-variant, catalogue-resilience, content-visibility, browser/media, mobile WebKit, reverse-proxy subpath, CodeQL, dependency, Docker, release-metadata, vulnerability, and migration checks passed.
- The automated release gate verifies supported upstream v2.1.1 and 2.1.4 migrations and an upgrade from the published Plus v2.5.2 image.
- The exact combined testing image passed controlled local and production-provider validation covering MFA, source refresh, Direct HLS, remux and transcoded playback, channel variants, persistent visibility, hidden favorites, TV Guide, Movies, Series, seeking, audio, subtitles, update checks, restart persistence, and application responsiveness.

---

### Security and container maintenance

The production image contains fewer unnecessary packages and tools, refreshes operating-system packages during release builds, and remains covered by dependency, CodeQL, container, and fixable High/Critical runtime vulnerability gates.
