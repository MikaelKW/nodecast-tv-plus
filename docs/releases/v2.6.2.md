# NodeCast TV Plus v2.6.2

v2.6.2 Improves TV Guide refresh safety, proxied HLS compatibility, and current dependency maintenance.

---

### Highlights

- The last complete TV Guide remains available while a replacement XMLTV feed is downloaded, parsed, and staged. A malformed, truncated, interrupted, or otherwise failed refresh reports the failure without erasing the active guide ([#425]).
- Successful EPG refreshes activate programme data and channel mappings together, avoiding mixed old and new guide generations. Valid empty feeds remain an intentional way to clear one source ([#425]).
- Proxied HLS playlists now use root-relative segment proxy URLs. Playback therefore inherits the browser-facing HTTP or HTTPS scheme and configured reverse-proxy base path instead of relying on an internal hop's detected scheme ([#413]). (@smyrnode)
- Compatible runtime compression and browser-test dependencies have been refreshed without introducing the deferred major framework or database-driver upgrades ([#412]).

---

### Upgrade from v2.6.1

Back up `/app/data`, pull the release image from either registry, and recreate the container with the same data volume and deployment secrets:

```bash
docker pull ghcr.io/mikaelkw/nodecast-tv-plus:2.6.2
```

or:

```bash
docker pull mikaelkw/nodecast-tv-plus:2.6.2
```

No manual database migration is required. EPG replacement staging uses temporary database state and does not add a persistent schema migration. Preserve the existing strong, distinct `JWT_SECRET` and `SESSION_SECRET` values, and preserve `TOTP_ENCRYPTION_KEY` when authenticator-app 2FA is in use.

Stable tags for this release are `2.6.2`, `2.6`, and `latest`.

To roll back, stop the upgraded container, restore the pre-upgrade data backup, and recreate the container with 2.6.1 and the original deployment secrets. Do not assume that simply starting an older image against upgraded data is a safe rollback.

---

### Validation

- Controlled hands-on EPG testing established an original guide, rejected a deliberately truncated replacement while retaining the original, and then activated the following valid replacement.
- Proxied HLS coverage verifies HTTPS with a plain-HTTP upstream hop, ordinary HTTP, and reverse-proxy subpaths while retaining playback authorization and base-path routing.
- Large synthetic EPG imports keep the active guide readable while replacements are staged, with explicit failure, recovery, concurrency, empty-feed, source-deletion, and restart-cleanup coverage.
- Automated release gates cover application and browser/media behavior, mobile WebKit, reverse-proxy subpaths, dependency and runtime-image scanning, CodeQL, container health, and supported migrations.
- Migration validation targets supported upstream v2.1.1 and 2.1.4 data and the published Plus v2.6.1 image. Final release artifacts are checked for both `linux/amd64` and `linux/arm64` and matching registry aliases.

---

### Known limitations and deferred follow-up

- A failed EPG refresh deliberately leaves the previous guide active. Correct the feed or connectivity problem and retry the refresh to replace it.
- Reverse-proxy deployments still need `APP_ORIGIN` and `TRUST_PROXY` values appropriate to their topology. Root-relative playlist URLs prevent the application from forcing the wrong browser-facing scheme; they do not replace correct proxy configuration.
- The unreproduced failed Home-favourite startup report remains tracked in [#361].
- Major framework and database-driver dependency upgrades remain deferred for separate compatibility work.
