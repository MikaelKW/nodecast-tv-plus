# NodeCast TV Plus v2.7.1

v2.7.1 improves administrator-account safety and Live TV catalogue refresh reliability, and includes dependency updates.

---

### Highlights

- Preserve at least one administrator during overlapping account role changes and deletions. A conflicting operation fails clearly, while other successful account changes remain saved ([#498]).
- Load the Live TV source list before refreshing its catalogue after M3U or Xtream synchronization. Synchronizing a source before the first Live TV visit no longer leaves the channel list empty until a browser refresh. Keep an available selected source filter during synchronization ([#361]).
- Update dependencies and retain the existing protected application, browser, migration and container checks.

---

### Upgrade from v2.7.0

Back up `/app/data`, pull the release image from either registry, and recreate the container with the same data volume and deployment secrets:

```bash
docker pull ghcr.io/mikaelkw/nodecast-tv-plus:2.7.1
```

or:

```bash
docker pull mikaelkw/nodecast-tv-plus:2.7.1
```

No manual database migration is required. Preserve the existing strong, distinct `JWT_SECRET` and `SESSION_SECRET` values, and preserve `TOTP_ENCRYPTION_KEY` when authenticator-app 2FA is in use.

Stable tags for this release are `2.7.1`, `2.7`, and `latest`. The `2.6` tag remains on the previous release line.

To roll back, stop the upgraded container, restore the pre-upgrade data backup, and recreate the container with 2.7.0 and the original deployment secrets. Do not assume that simply starting an older image against upgraded data is a safe rollback.

---

### Validation

Release gates cover concurrent account changes, normal account management, source synchronization followed by Live TV navigation, grouped and flat channel lists, source filtering, playback, authentication and Diagnostics.

Combined validation includes application and browser/media checks, mobile WebKit, iPhone Safari, reverse-proxy subpaths, dependency and runtime-image checks, CodeQL, container health and supported migrations. The migration matrix includes upstream v2.1.1 and v2.1.4 and published Plus v2.6.2 and v2.7.0. Final publication checks verify both `linux/amd64` and `linux/arm64` image identities and matching registry aliases.

---

### Known limitations

- The catalogue correction covers the reproduced source-synchronization path in [#361]. Other intermittent empty-catalogue reports, including unavailable Home favourites, are not established as having the same cause.
