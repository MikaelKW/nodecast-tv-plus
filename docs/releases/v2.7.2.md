# NodeCast TV Plus v2.7.2

v2.7.2 improves iPhone and iPad playback compatibility and updates dependencies to address security vulnerabilities.

---

### Highlights

- Use the compatible HLS remux session for channels that require remuxing on iPhone and iPad, including iPadOS desktop browsing. Browsers without HLS.js support use native HLS playback when available. Supported browsers retain the existing HLS.js path, and macOS Safari retains direct remux playback ([#520]). Thanks to @StevenVBeek.
- Update dependencies to address security vulnerabilities. See the [changelog](https://github.com/MikaelKW/nodecast-tv-plus/blob/main/CHANGELOG.md) for the affected packages and CVEs.

---

### Upgrade from v2.7.1

Back up `/app/data`, pull the release image from either registry, and recreate the container with the same data volume and deployment secrets:

```bash
docker pull ghcr.io/mikaelkw/nodecast-tv-plus:2.7.2
```

or:

```bash
docker pull mikaelkw/nodecast-tv-plus:2.7.2
```

No manual database migration is required. Preserve the existing strong, distinct `JWT_SECRET` and `SESSION_SECRET` values, and preserve `TOTP_ENCRYPTION_KEY` when authenticator-app 2FA is in use.

Stable tags for this release are `2.7.2`, `2.7`, and `latest`. The `2.6` tag remains on the previous release line.

To roll back, stop the upgraded container, restore the pre-upgrade data backup, and recreate the container with 2.7.1 and the original deployment secrets. Do not assume that simply starting an older image against upgraded data is a safe rollback.

---

### Validation

Release gates cover iPhone/iPad HLS remux selection, native-HLS fallback, the existing HLS.js path, playback and channel switching, source synchronization, authentication and Diagnostics.

Combined validation includes application and browser/media checks, mobile WebKit, iPhone Safari, reverse-proxy subpaths, dependency and runtime-image checks, CodeQL, container health and supported migrations. The migration matrix includes upstream v2.1.1 and v2.1.4 and published Plus v2.6.2, v2.7.0 and v2.7.1. Final publication checks verify both `linux/amd64` and `linux/arm64` image identities and matching registry aliases.
